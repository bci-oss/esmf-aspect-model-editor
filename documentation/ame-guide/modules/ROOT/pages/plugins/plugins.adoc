[[plugins]]
= Plugins

Plugins extend the Aspect Model Editor without installing a new version, e.g. with an importer for another file format or a generator that exports the open Aspect Model.
A plugin is a `.zip` archive provided by its developer; it can add backend functionality and a user interface that opens from the menu bar or the toolbar.

WARNING: Plugins are not sandboxed: they run with the same rights as the editor and can read and change all your files.
Only install plugins from sources you trust.

[[install-plugin]]
== Install a plugin

. Open the xref:getting-started/settings.adoc[Settings] and select *System Configuration* > *Plugins*.
. Click *Install plugin…* and select the plugin archive (`.zip`).
+
The plugin is listed with the state *Restart required*.
. Click *Restart backend* to start the plugin.
Open models, including unsaved changes, stay open.

Once the plugin is *Active*, its commands are available in the desktop app; the plugin decides where they appear.
Running a command opens the user interface of the plugin in a dialog.

[[use-plugins]]
== Use plugins

Plugins offer two kinds of commands:

* *Import* commands create new Aspect Models, e.g. from a file in another format.
The models are opened in the editor and are not saved until you save them.
* *Generate* commands create files from the open Aspect Model, e.g. an export to another format.
The desktop application asks you where to save generated files.
They work on a copy of the model including unsaved changes and do not change it.

Depending on the plugin, a command is available

* in the menu bar under *File* > *Import*, under *Generate* or in an own *Plugins* menu,
* in the toolbar under the *Plugins* button (puzzle piece).

Generate commands are disabled while no model is open.
If an element is selected in the editor, a generator knows which one, e.g. to export only this element.

Installing an archive of an already installed plugin updates it; data of the plugin is kept.
The new user interface of an updated plugin is used after a restart of the application.

[[manage-plugins]]
== Manage plugins

The list under *Installed plugins* shows the name, version, description and state of each plugin.
Use the *More actions* button of a plugin to

* *Disable* a plugin: it is not started anymore and its commands disappear, but it stays installed.
* *Enable* a disabled plugin again.
* *Remove* a plugin including its data.

All changes take effect after clicking *Restart backend*.
Removing a running plugin restarts the backend right away, because the plugin stays loaded until the backend stops.

[cols="1,3"]
|===
| State | Meaning

| Active | The plugin is running.
| Restart required | The plugin was installed, updated, enabled or disabled; restart the backend to apply the change.
| Disabled | The plugin is installed but not started.
| Failed | The plugin could not be started; the error is shown below it. Contact the developer of the plugin.
| Not running | The plugin is enabled but was not started, e.g. because the backend was started before its installation.
|===

TIP: A plugin that fails to start does not affect the editor or other plugins.

[[plugin-files]]
== Where plugins are stored

Plugins are stored in the folder `aspect-model-editor/plugins` in your home directory.
To develop own plugins, see xref:plugins/develop-plugins.adoc[Develop plugins].
